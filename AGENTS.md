# Ikigai Time Deposit Kata — Agent Instructions

## Scope
- Read the original README.md as the primary source of requirements.
- Work exclusively on the Java implementation and relevant documentation.
- Use Java 17 and Maven.
- Preserve required public contracts and existing business behaviour.
- Do not modify implementations in other languages.

## Engineering standards
- Follow pragmatic Hexagonal Architecture and SOLID principles.
- Separate domain, application and infrastructure layers.
- Avoid over-engineering and unnecessary dependencies.
- Prioritize business correctness, maintainability and readability.
- Handle financial calculations carefully.

## Testing
- Write characterization tests before refactoring.
- Cover business rules, edge cases and boundary conditions.
- Use descriptive test names and meaningful assertions.
- Avoid unnecessary mocking and redundant tests.
- Run relevant tests after each change.
- Never fabricate test results.

## Development workflow
1. Requirements analysis.
2. Existing code analysis.
3. Identify defects and missing functionality.
4. Write tests and review coverage.
5. Refactor incrementally.
6. Implement missing requirements.
7. Review architecture and dependencies.
8. Remove dead code.
9. Run the complete test suite.
10. Complete documentation.

## Git and AI transparency
- Make small, logically atomic changes.
- Do not commit or push without explicit approval.
- Document actual AI prompts, configurations and technical decisions.
- Clearly distinguish confirmed requirements from assumptions.
- Never fabricate development history.

## Execution
- Explain important decisions and their justification.
- Stop after completing each requested phase.
- Do not proceed to subsequent phases without approval.
- Ensure the candidate can understand, explain and extend the final solution during a live coding interview.
